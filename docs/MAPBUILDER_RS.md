# MapBuilder на Rust — стан на 2026-11-05

Гілка `feature/mapbuilder-rs`. Мета — щоб місто гравця збиралося за хвилину-дві, а не за 20+ хвилин.
Дизайн вікна робиться окремо, промпт для Figma лежить у [MAPBUILDER_FIGMA_PROMPT.md](MAPBUILDER_FIGMA_PROMPT.md).

## Принцип

Етапи переносяться по одному. Нативний етап пише **те саме**, що Python-етап, який він замінює.
Це перевіряється об'єкт за об'єктом або байт за байтом на справжніх даних (Київ). Python лишається
запасним шляхом: `EARTHNG_NATIVE=0` вимикає все нативне.

Нативний код живе в `rust/` (Cargo workspace):

| Крейт | Що робить |
| --- | --- |
| `osm` | Читання PBF через mmap (osmpbf), власний PBF-писач, правила `osm_select`, нарізка тайлів (`cut.rs`), джерело `Map detail` (`mapsrc.rs`) |
| `geo` | UTM за рядами Крюгера (сумування Кленшоу), `fast_sources.Frame` без PROJ |
| `kernels` | `earthng_native.dll` для ctypes: CG профілів доріг, DEM Terrarium (`terrain.rs`) |
| `pack` | Формат клітинок EGB2 (`format.rs`), графи маршрутизації EGR1 (`routing.rs`) |
| `cells` | `compile_cell` + кодер: індекс через SQLite, сцени, GEOS із shapely (`geos.rs`, завантажується під час роботи), семантика numpy (`numeric.rs`) |
| `mapbuilder` | `earthng-mapbuilder.exe`: підкоманди `cut`, `routing`, `map-source`, `compile` |

`earthng/native_tool.py` знаходить exe і dll: спершу в `bin/` (реліз), потім у `rust/target/release`
(checkout, `cargo build --release` у `rust/`).
`prepare_release.py` кладе їх у `bin/` ZIP-а MapBuilder: збирає `cargo build --release --locked` з чистого
`rust/` тієї ж ревізії й додає `bin/THIRD_PARTY_RUST.txt` (ліцензії крейтів). `--no-native` залишає
реліз лише на Python.

### Клітинки нативно

Python-воркер частини блоку передає `earthng-mapbuilder compile` клітинки, план читання сцен
(`_scenery_plan`, той самий обхід, що `_scenery`) і параметри DEM. Rust повертає payload-и, а ті клітинки,
яких він не покриває, повертає Python: близько до рівня моря (`_coast`), з `water=harbour` (`_flood`),
з landcover або при будь-якій помилці. Python тоді компілює їх сам або піднімає свою помилку.
Геометрія йде через `geos_c` зі shapely (той самий build GEOS 3.14), тому кліп, `make_valid`,
`difference` і `union_all` дають ті самі вершини. Сцени зберігаються у двійковому форматі `ESC1`
(`fast_sources.write_scene`), який читають обидві сторони. Сцени стоять у черзі перед частинами,
а `.lock` не дає читати тайл двічі.

Нативний шлях вмикається лише в збірці зі спільними сценами (місто, мало блоків). Вся країна
поки йде через Python: її воркери тримають сцени в пам'яті.

Час Rust на 36 центральних клітинках Києва (2.9 с проти 7.4 с у Python): DEM 0.7, `partition` 1.3,
запит, сцени й решта — 0.9 с.

`Map detail` (`build_map.py`, пошук населених пунктів і оглядові дороги всієї країни) іде у фоні від
нарізки до експорту, паралельно з DEM та індексом. Кешується на PBF, тож рахується тільки при першій
збірці країни. Для першого міста він на критичному шляху, бо довший за індекс, тому прискорений:

| Країна | Було | Стало | Що змінилося |
| --- | ---: | ---: | --- |
| Естонія (124 МБ) | 11.0 с | 3.4 с | |
| Аргентина (433 МБ) | 81.1 с | 30.2 с | читання PBF 4.5 с (`map-source`), растр 9.4 с |

Що зроблено: замість osmium PBF читає `earthng-mapbuilder map-source` (тайли доріг, потім вузли, на всіх
ядрах). Спрощення ліній іде батчами в один виклик GEOS на рівень. Растрові оверв'ю рендеряться в потоках
(Pillow відпускає GIL на ресемплі й стисненні), а JSON рівня читається раз, а не на кожен zoom.
Spool відкриває part-файл раз на 64 МБ, а не раз на 128 рядків (8000 відкриттів на Аргентині).
Усі файли (`places.json`, тайли, PNG, `index.json`) ідентичні osmium-шляху на Естонії, Албанії й
Аргентині; `test_map_data` перевіряє це на зразку при кожному прогоні.

## Де тепер чекає користувач

Перше місто в Україні:

1. **Завантаження PBF країни**: 882 МБ. Це хвилини, і жоден код на клієнті їх не прибере.
2. Нарізка боксу: 12 с.
3. DEM: кілька тайлів z12 на місто, паралельно.
4. Індекс: 41 с. Він однопотоковий, з них CG 15 с упирається в пам'ять (матвек ~75 МБ на ітерацію).
5. Експорт: 16.4 с. Читання 30 сирих тайлів OSM (`build_scene`, osmium + правила `fast_style`,
   `retail`, `venues`) — 7.6 с і 87 с процесора: найважчий тайл сам по собі 3.85 с, а в паралелі
   12 процесів удвічі повільніші. Потім клітинки — 6 с, пакування й маршрутизація — 3 с.

## Наступні кроки, за виграшем

1. **Тайли з сервера замість PBF країни.** Нарізка вже детермінована: `index.json` має sha256
   кожного тайла 0.05°. Сервер тримає нарізку країн (або планети), а клієнт качає тільки тайли свого
   боксу (кілька МБ для міста). Так зникають кроки 1–2 і `Map detail`. Цей самий сервер потрібен
   для спільних правок і готових паків, тому це одна архітектура, а не дві.
2. **Нативні сцени (`build_scene`).** Тепер це половина експорту міста. Треба зібрати мультиполігони,
   як osmium (area assembler), і перенести класифікацію `fast_style`/`retail`/`venues`. Правил там
   багато, тож їх варто описати даними, щоб Python і Rust читали одну таблицю, а не дублювали код.
   Клітинки (зроблено) далі:
   - берег (`_coast`: `line_merge`, `distance`, `line_locate_point` — усе є в GEOS);
   - гавані (`_flood`);
   - нативний шлях для всієї країни, не лише міста;
   - `partition` швидше: пропускати `union`/`difference`, коли сусіди не перетинаються, але лише з
     доказом, що `equals` дає те саме.
3. **CG.** Колонки CSR уже u32 (−третина трафіку, той самий результат). Симетричне зберігання
   (половина матриці) або кращий передобумовлювач скоротять ще вдвічі-втричі. Але тоді висоти
   зміняться в межах допуску CG (1e-3), тож це рішення користувача, а не тихий перехід.
4. **`Map detail`**: PBF уже нативно (вище). Далі растр (9 з 30 с на Аргентині) — рендер ліній у Rust
   (tiny-skia) змінить пікселі, тож лише з перевіркою на око; або прибрати весь крок для міст, якщо сервер
   віддає готовий `map/` країни.
5. **Більше джерел одночасно**:
   - DEM Copernicus GLO-30 (COG, HTTP range-запити) як точніша альтернатива Terrarium;
   - ESA WorldCover COG (range-запити по боксу, а не тайли на диску);
   - будівлі Overture (GeoParquet, фільтр рядків за bbox).

   Усе це качається паралельно з нарізкою, бо залежить лише від боксу.

## Як перевіряти

- Rust: `cargo test --release` у `rust/`.
- Python: `.venv\Scripts\python.exe -m unittest test_native_tool test_country test_mapbuilder`
  з `earthng/`. Тести нативного пропускаються, якщо exe/dll не зібрані.
- Паритет на даних: зібрати той самий пак з `EARTHNG_NATIVE=0` і без нього та порівняти
  розпакований вміст кожного файла ZIP. Індекс порівнювати по `features.data` (`prof`) і `nodes.h`.
