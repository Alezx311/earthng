# FMOD як точка входу нативного моста

Дослідження 15.11.2026, лише читання, запуску гри та змін її файлів не було.

## Локальні ознаки

У встановленому `Bin64/BeamNG.drive.x64.exe`, властивість версії файлу
**0.40.5.0.302427**, є рядок помилки
`smCoreSystem->loadPlugin() was unable to load plugin '{}': {}`. Поруч із
рядками ініціалізації аудіо перелічені `BeamNGBlendLayerDSP.dll`,
`fmodDistanceFilter.dll`, `fmodGain.dll`, `logi_fmod.dll`; усі чотири файли
існують у `Bin64`. У перших трьох знайдено рядок `FMODGetDSPDescription`.
Це сильні статичні ознаки застосування нативних FMOD-плагінів, **не** динамічне
доведення моменту завантаження, наявності довільного пошуку плагінів чи їх
доступності з Lua. Перевірка полягала в переліку файлів, читанні версії PE та
скануванні ASCII-рядків; таблицю експорту і виклики дизасемблером не перевіряли.
Пошук цих назв та `loadPlugin` у встановленій Lua-теці не знайшов відповідників.

## Що каже FMOD

[Документація FMOD 2.02](https://www.fmod.com/docs/2.02/api/dsp-plugin-api-guide.html)
описує DLL, яка експортує `FMODGetDSPDescription`, і зазначає, що код гри має
завантажити плагін або зареєструвати його до завантаження об'єкта, який ним
користується. Сканування теки плагінів FMOD Studio стосується **редактора
Studio**, а не довільної гри. API має `System::loadPlugin` та
`System::setPluginPath`, однак наявність API в рушії не доводить, що його
доступно модам або що гра сканує теку модів. Версію SDK для плагіна треба
звірити з реальною версією FMOD у працюючій грі; жодна не вимірювалась тут.

[Співробітник BeamNG у 2021 році](https://www.beamng.com/threads/fmod-how-to-add-custom-sounds-to-cars.82586/)
зазначив, що модинг FMOD не підтримувався. Повідомлення старе і само по собі
не встановлює політику або поведінку 0.40.5. Автор [інтеграції EngineSim](https://www.reddit.com/r/BeamNG/comments/1xa8ycq/i_connected_enginesim_with_beamng/)
повідомляє про FMOD DLL і окрему програму симуляції, але відкритий вихідний код
цієї конкретної інтеграції та метод інсталяції/завантаження не перевірені.
Це зачіпка, а не доказ інтерфейсу сторонніх FMOD-плагінів у ZIP.

## Що це дає EarthNG

Якщо гра має підтримуваний механізм завантаження стороннього DSP, такий плагін
може виконувати нативний код у процесі гри. Але потрібні **два незалежні
докази**: хто реєструє/завантажує DLL і як Lua надійно обмінюється великими
пакетами з нею. FMOD-параметри призначені для звуку; немає доказу доступності
універсальної двосторонньої передачі довільних байтів із GE Lua. Завантаження
плагіна також не скасовує sandbox Lua.

Важкі завдання не можна виконувати синхронно в аудіообробці: плагін, якби був
підтриманий, мав би передавати роботу окремому обмеженому пулу й повертати
результати поза аудіоколбеком. Треба виміряти не лише швидкість Rust, а й
вартість обміну, час кадру та можливі перебої звуку.

## Наступна перевірка

Знайти підтверджений конфігураційний або Lua API для **нової назви** DSP DLL,
який працює без підміни файлів гри; якщо знайдено — зробити ізольований тест
з одного завантаження, ідентифікації процесу, контрольного повідомлення та
коректного завершення. За відсутності такого інтерфейсу не заявляти, що FMOD є
універсальним завантажувачем. Сканування рядків і назви stock-DLL для цього
недостатні.

Пошукові запити: `BeamNG EngineSim fmod plugin bridge github source`,
`BeamNG fmod custom plugin load plugin dll mod`, `site:fmod.com/docs
"FMODGetDSPDescription" plugin`, `"BeamEngineSimBridge" "FMOD" github`.
